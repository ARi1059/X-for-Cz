### 1.1 本轮复查结论

本轮在同一 URL 上复核了 **1440×1000、1440×700、1280×800、1100×900、1024×768、900×1000、834×1112、390×844（DPR 2）、320×568（DPR 2）**，覆盖默认停用、模拟可用／强调、悬停、键盘焦点、站点说明弹层和注入失败反馈。

**一句话结论：** 人像与姓名的关系已经成立，问题集中在“五个入口仍像一张表单”——同权卡片、重复箭头、金色分散、没有入场；失败反馈还会把整列入口推开。下一轮应把入口做成一本目录（**1 个主入口 + 4 条细线行**），把动效收束为一次“翻开”的节奏。

| 维度 | 当前看到的效果 | 判断 |
|---|---|---|
| 构图 | 1440 下人像 800×1000、从 x=640 开始；左栏 300px；人物面部中心约 69% | 成立；宽而短的桌面（1440×700）中间空区增至约 494px，偏空 |
| 姓名 | 43px 宋体、字距 3px；扫光约 0.3s 后开始、2.2s 结束于 `-100%` | 方向对；终态停在另一个渐变位置（整体更亮、右侧留高光），没有回到起点，扫光结束后姓名的明度被永久改变 |
| 入口 | 5 张 300×58 卡片、8px 间距；每行有编号、前置图标、标签、状态、尾部箭头 | 五卡同权，像设置菜单；X 行出现两个同向箭头；停用与可用只差底色 |
| 金色 | 姓名、头像描边、eyebrow、编号、图标、箭头、状态、注脚、页脚 | 金色太分散，停用状态仍满屏金色，主入口不够明确 |
| 反馈 | 等待只改文案；失败在入口下方插入约 75px 面板 | 失败时整列重新居中，第 1–2 行上移 37.6px、第 3–5 行下移 37.6px |
| 入场 | 左栏没有入场；只有姓名扫光；弹层瞬时出现 | 首屏缺一个可感知的“翻开”，弹层缺 150–200ms 的过渡 |
| 手机 | 390 入口 171.6×59、标签与状态分两行；320 文档高 603px | 320×568 页脚第二行被截在首屏外；卡片边框在黑裙上几乎消失 |

> 证据范围：该体验目前只在本地开发环境由 `?experience=light-gallery` 打开（`page.tsx` 对 `NODE_ENV`、本机 host 和参数做了限制），本轮结论只代表开发预览，不代表线上已发布版本。五入口全部停用是本机草稿内容状态；“可用／强调”截图是用 DOM 注入做的视觉对照，不是功能验收。

## 3. P1：优先实施

> V01–V04 为第一阶段 P1，已完成；本轮新增的 P1（V09–V10）放在第 6 节展开，避免与已完成项混在一起。

### V01 · 照片清晰度

**优化前证据：** 背景与首页五张照片实际均为 **512×640**，头像为 **320×320**。背景在桌面铺到 1000 CSS px 高、手机铺到 844px 高，超过当时源图高度。服务端 2000px 是输出上限。

**2026-10-30 进展：** 已收到 **2090×3135** 原片，匹配既有 4:5 构图，导入 **1600×2000 WebP，约 212 KiB**。人像背景与首页第五张同步更新，其余四张照片及头像保持原样。桌面／手机共同尺寸的渲染位置和大小与更新前一致；八尺寸无溢出，原片和旧媒体均保留。仅更新本地草稿第五张媒体引用，正式发布版本仍为 1。

**2026-11-02 复核：** 1440×1000、DPR 1 下背景显示 800×1000（源图宽 2×）；390 DPR 2 显示约 675 CSS／1350 设备 px；834 DPR 2 按显示宽度推算约 890 CSS／1780 设备 px，**超出 1600px 展示图约 11%**，平板上有轻微上采样。桌面与手机清晰度成立，平板与超大屏需要衍生图（见 V08）。真机、首屏等待时间仍待测量。

**后续核对：** 浏览器截图已比较面部、发丝、衣料及构图；其他照片收到对应原片后再逐张处理。详见 [高清背景接入记录](/Users/macbook/Documents/推特创作者计划/docs/M3-高清背景接入.md)。

### V02 · 手机文字与布局

**优化前证据：** 390px 屏幕左栏宽 156px，320px 屏幕为 128px。装饰英文约 4.5px、状态字 8px、页脚字 9px；窄短屏入口字降至 11px。

**建议试验值：**

| 元素 | 试验方向 | 约束 |
|---|---|---|
| 手机装饰英文 | 隐藏过小的装饰字 | 保留姓名与入口的清楚层级 |
| 入口文字 | 13–14px | 窄屏检查换行和五入口可达性 |
| 状态文字 | 10–11px | 与入口名称有明确层级 |
| 390px 下的左栏 | 168–176px | 对比人物面部与文字的间距 |
| 姓名 | 可试 26–28px | 与头像、栏宽一起比较 |

**第一阶段结果：** 手机姓名 26px、入口 13px、状态 10px；隐藏过小装饰英文。左栏为 `min(176px,44vw)`，390px 下约 172px、320px 下约 141px。短屏保留字号并允许自然纵向滚动；手机背景按视口等比固定，避免随内容增长拉大人物。

**2026-11-02 复核：** 390 下左栏 171.6px、姓名 26px、入口 13px／状态 10px；320 下左栏 140.8px、入口 55px 高；均无横向溢出。390 下五个入口与页脚首行在首屏内；320 下页脚第二行在首屏外（见 V13）。姓名与状态字号可读，但入口的五卡结构让 390 下的列表高达约 323px，是短屏压力的主因（见 V09）。

**核对：** 390×844、320×568 下逐项阅读五入口，确认人物面部无遮挡、文字完整、无横向溢出。

### V03 · 页脚触控

**优化前证据：** 手机页脚三个操作的按钮实际高度约 28px；主入口已经达到 49–59px。

**建议：** 页脚以约 44×44px 为触控目标，文字继续保持轻量。根据两列布局增加行距、区域高度与底部安全区，避免扩大透明点击范围后发生重叠。主入口沿用现有高度。

**第一阶段结果：** 页脚操作至少 44×44px，手机两列各两行、行间距 4px、字号 11px。底部采用 `max(14px, env(safe-area-inset-bottom))`；九尺寸的点击区无重叠。带底部手势条真机的末行显示仍待核对。

**2026-11-02 复核：** 390 页脚高 117px、320 高 117px；四个操作均 44px 高。320×568 的文档高 603px，页脚第二行（重新确认年龄／返回原版）落在首屏之外，截图正好切在文字上。四个操作在 296px 内可以排成单行（见 V13），预计页脚降到约 64px，短屏不必滚动。

### V04 · 按钮完整状态

**优化前证据：** 当前五入口均“暂未开放”，第三入口仍有明显金色强调。现有导航流程有等待与防重复处理，但等待状态未显示到具体入口。

| 状态 | 建议呈现 |
|---|---|
| 可用 | 象牙文字、细金边，沿用当前轻按压 |
| 主入口可用 | 保留一处香槟强调 |
| 暂未开放 | 清楚的状态字、弱化箭头；停用状态覆盖主强调底色 |
| 正在打开 | 当前入口显示短状态，按钮宽高保持稳定 |
| 打开失败 | 靠近入口显示原因与重试操作 |

**第一阶段结果：** 两视图使用入口级等待、失败原因与重试；同步锁阻止同一轮快速连点，停用入口移除强调底色，等待提示预留位置。重试时焦点回到入口，版本变化后保持静态浏览偏好。使用隔离测试数据核对，不填真实外链，真实外跳结果另行记录。

**2026-11-02 复核：** 默认五入口全部停用时，五行仍保留金色编号、金色图标和暖金色状态，视觉上像五个可用入口；“等待”只改文案，没有进度感；“失败”插入约 75px 面板，导致整列重新居中（见 V11）。建议把等待／失败状态收进入口行内，详见 V10、V11。

## 4. P2：统一视觉与动效

### V05 · 品牌与材质

当前确认页／默认首页使用 `GQ· / PRIVATE EDITION`，人像页使用 `GU QINGTANG / PRIVATE EDITION`，按钮圆角也存在约 7px 与 4px 的差异。

**2026-11-02 品牌对照：**

| 项目 | 现状 | 建议 |
|---|---|---|
| 字标 | 首页与确认页为 `GQ` 组合；人像页为 `GU QINGTANG` | 一套可伸缩的 lockup：窄面（确认页／手机顶栏／favicon）用 `GQ` 字标；宽面（人像页桌面、首页）用 `GU QINGTANG` 全称。两者共用同一字距、金色和竖分隔线规则，不做两套气质 |
| 圆角 | 首页卡片 7px、高 66px；人像页 4px、高 58px；管理端自成一套 | 公共页统一 **4px**（若 V09 采用细线行，圆角只保留在主入口 2–4px）；管理端保留自己的圆角，不混入公共页 |
| 功能字号 | 7px 英文装饰、8px 版本行、9px 页脚／状态 | 功能文字 ≥ 10px；7–8px 只留给纯装饰英文；页脚 9→10px，手机 11px |
| 金色 | `#dbb886`、`#c7a678`、`#cba774`、`#f2d6af` 四套 | 收成 3 个用途：**线** `#d8b48a`（低透明）、**字** `#e6c79b`、**焦点** `#f4dcb8`；错误色 `#d8a08a` 单独 |
| 字体角色 | 宋体同时用于章节标题、姓名、注脚、弹层标题；首页另有 `After hours.` 斜体展示 | 每页只允许一个 display 时刻：人像页是姓名，首页是 `After hours.`；章节标题改无衬线 10–11px，注脚与弹层标题可用宋体 |
| 材质 | 深色渐变 + 1px 金边 + 极轻内高光 | 保留；增加 2–3% 静态胶片颗粒（只在背景层，不盖文字），压住暗部色带，统一照片与 UI 的质感 |

建议确定一套共同规则：暖黑底、象牙文字、哑光香槟细线；统一标识组合、标题字体、圆角、图标笔画、焦点颜色与状态。各页面保留自己的布局比例，主强调集中在姓名与一个可用入口。

站点说明当前仅一行成年提示。有已确认的站点用途、外部链接说明等内容时补充；内容少时缩小弹层。联系渠道沿用真实配置。**本轮复核：** 弹层 480×133、标题 26px、正文 12px，一行内容时显得空；建议宽度 `min(400px, calc(100% - 32px))`、标题 20–22px、正文 13px、内边距 20–24px，并在标题上加一条 1px 金线。

### V06 · 选中照片

本轮已确认“下一张”正确切至 **2/5**，照片与计数对应。现有细金边和标题变色可进一步强化。

优先试验**底部短金线＋标题轻提亮＋计数同步**，状态变化约 200–300ms，相邻照片保留原色、维持原生滑动。若另行比较“一张主图＋下一张局部”的排版，需要同时评估同屏照片数量减少的取舍。

人像导航继续使用固定背景。背景换片仅作为未来可选需求，届时再比较图片解码后 350–500ms 的交叉淡入。

### V07 · 动效节奏

当前默认首页身份入场单段约 1.05s，最后一个入口约 1.5s 完成。人像页没有左栏入场，只有姓名扫光；弹层瞬时出现。本轮已对 light-gallery 做逐帧测量。

| 场景 | 实测现状（2026-11-02） | 本轮建议 | 核对重点 |
|---|---|---|---|
| 左栏入场 | 无 | 420–480ms；身份组先入，五个入口错峰 25–30ms；位移 8px；60–80ms 后开始 | 首屏 300ms 内可读，五个入口 700ms 内可点 |
| 图片首次显现 | 无淡入；解码前是径向渐变 | 900ms opacity .85→1 + scale 1.012→1；或 LQIP 200ms 交叉淡入 | 无白闪、无空图跳变 |

这些时长尚未做方案对比。继续保留手机静态环境光、离屏暂停、卸载清理和减少动态时直接呈现最终状态。默认首页的 1.05s／1.5s 入场也应一并压到 700ms 内，避免两页节奏相差一倍。

**观察：**

**建议：**

- **宽屏不填满，做“栏”。** 在 `min-aspect-ratio: 16/9` 且高度 < 800 时，不要把照片放大到裁掉人物；在左栏右侧 32px 加一条 1px、8% 的竖向细线，从标题下沿到注脚下沿，把空区变成版心留白。或者把左栏宽度从 300 提到 320–336，减少空白，不改照片。
- **手机边框可见性。** 390 的压暗已经是 .92／.64／.10，问题不是压暗不够，而是 1px 边框 `rgba(156,134,99,.3)` 在黑裙上几乎消失。建议把分隔线／边框提到 `rgba(216,180,138,.28–.36)`，并在行顶加 1px `rgba(255,231,189,.08)` 内高光；不要再整体加深压暗，以免压掉人物。若采用 V09 的细线行，分隔线在手机上也应至少 .22，否则照片上的边界会断。
- **短屏页脚单行。** 四个操作在 296px 内可以排成一行：44 + 66 + 44 + 44 + 3×8 = 222px（11px 字），仍满足 44px 触控；页脚从 117px 降到约 64px，320×568 的文档高可回到 550px 左右。若仍不够，把“重新确认年龄”收进站点说明弹层，但保留“站点说明”和“返回原版”直达。
- **平板清晰度。** 为 834 这类 DPR 2 平板增加 2000px 宽的展示衍生图，或在 `display` 变体上按 `viewport width × DPR` 选择 1600／2000；不要直接把原片 2090×3135 全量下发。
- **首图占位。** 背景解码前现在是纯径向渐变；用旧的 40KB 展示图或 20px LQIP 做 `blur(24px)` 占位，200ms 交叉淡入，避免慢网出现“只有文字没有人物”的空场。`fetchpriority="high"` 只给背景这一张。
- **材质颗粒。** 在 `.lg-backdrop` 之上加一层 2–3% 的静态胶片颗粒（SVG feTurbulence 或 160px 噪声图平铺），`pointer-events:none`，不盖文字；暗部渐变更耐看，也把照片和 UI 拉到同一质感。

**验收：** 1440×700 与 1280×800 下，左栏与照片之间的空区不超过 340px，或不显得断裂；390 下卡片边框在黑裙上可见；320×568 首屏能看到五个入口和页脚四个操作；834 DPR 2 截图面部边缘不糊；慢网 3G 下首图 1s 内有可辨认占位。

### 6.6 参考案例：借什么、不借什么

以下页面于 2026-11-02 核对：Cori、PHOTOYOSHI、Rauno、Paco、Brian 为 Chrome 1440×1000 截图；Awwwards 采用 Refero 的样式拆解，未单独截图。外部站点会更新，引用的是当天的形态。

| 参考 | 可借鉴 | 不照搬 |
|---|---|---|
| [Cori Corinne](https://www.coricorinne.com/)（[Refero 拆解](https://styles.refero.design/style/2c18e573-0ffb-4f0d-848c-ff72a5839fd3)） | 一个超大衬线姓名当封面；导航用安静的无衬线；只留发丝级顶栏；照片满版、无圆角无阴影；除姓名外不出现第二个 display 字体 | 奶油浅色纸面、180px 姓名（我们左栏只有 300px）、“零组件”到没有触控目标 |
| [Awwwards](https://www.awwwards.com/)（[Refero 拆解](https://styles.refero.design/style/a77a7289-3438-46ba-8194-214739e47514)） | 超大字号 + 满版摄影 + 一条浮动导航轨；近乎单色，只留一个强调色；用“尺度”而不是“样式”建立层级 | 8–14px 圆角卡片、浅灰底、把强调色用在多个元素 |
| [PHOTOYOSHI](https://photoyoshi.com/)（[Garden Eight 获奖记录](https://patio.garden-eight.com/en/updates/awards-awwwards-site-of-the-day-photoyoshi/)） | 画面大部分压成灰雾，只让少量对象保留颜色／注意力；底部用超大类别字压住画面；导航 chrome 极轻 | 网格与多图并列；我们只有一张人像，不要为了“像摄影集”增加照片 |
| [Rauno Freiberg](https://rauno.me/) | 顶部用极小刻度表示进度／位置；交互细节克制；不靠常规导航条 | 整页幻灯片结构、亮黄色块；与我们的暖黑不兼容 |
| [Paco Coursey](https://paco.me/) | 窄栏排版、链接以文字和下划线为主、留白大；内容本身承担界面 | 纯文本列表；手机需要 44px 触控目标，不能只靠下划线 |
| [Brian Lovin](https://brianlovin.com/) | 章节标签 12px 灰字 + 纯文本行；头像、姓名、简介、社交图标形成一条安静的主线 | 整页无品牌色、无背景；我们需要人像与暖金作为识别 |

**共同结论：** 这些站点的“高级感”来自**少量元素 + 大尺度 + 发丝线**，不是更多金色、更多卡片或更多动效。我们应减少入口的容器感，把金色集中到姓名与一个主入口，把动效集中到一次入场和一次扫光。

## 7. 建议推进顺序与技能

1. **结构与材质：** V09 + V10 + V05。先把五卡改成 1+4 细线行，收束金色，统一字标／圆角／字号 token；这一步不需要改内容，截图变化最直接。
