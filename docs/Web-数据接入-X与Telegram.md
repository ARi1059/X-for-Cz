# Web 端接入 X API 与 Telegram Bot API

日期：2026-11-06  
范围：`web/` 站点只读展示层。不含运营 Bot 的订单、会员、留言数据，也不改变「运营 Bot ↔ 网站无接口」边界。

## 1. 接了什么

| 数据 | 来源 | 使用位置 | 失败时 |
|---|---|---|---|
| 账号粉丝数 | X API v2 `GET /2/users/by/username/:username` | 「个人简介」数据行 | 隐藏该行 |
| 最近帖文与媒体缩略图 | X API v2 `GET /2/users/:id/tweets` | 「预告」板块 | 保留粉丝数，提示进入预告频道 |
| 防丢频道人数 | Telegram Bot API `getChatMemberCount` | 「个人简介」数据行 | 隐藏该行 |
| 预告频道人数 | 同上 | 「个人简介」数据行 | 隐藏该行 |

浏览器只访问同源的 `GET /api/lab/story`，不直接持有任何 token，也不直接请求 X / Telegram。该接口只返回公开指标和公开帖文，不含访客数据、订单或会员状态。

## 2. 数据流与缓存

```text
页面 → GET /api/lab/story
         → 进程内缓存（默认 300 秒）
         → X API（粉丝数 / 时间线）
         → Telegram Bot API（两个频道人数）
```

- 缓存按进程保存；站点当前是单 Node 实例，符合现有部署形态。
- 并发请求共享同一次上游刷新，不会因多人同时打开页面重复消耗额度。
- X 返回 403（套餐或权限不足）后冷却 30 分钟；返回 429 时按 `x-rate-limit-reset` 冷却。
- Telegram 返回 429 时按 `retry_after` 冷却；400/403 只影响对应频道。
- 单个来源失败不会让整个接口失败，也不会把错误堆栈或上游响应返回给浏览器。

## 3. 配置

在 `web/.env.local`（0600，不入库）填写：

| 变量 | 必填 | 说明 |
|---|---|---|
| `X_BEARER_TOKEN` | 否 | X API v2 的 Bearer token，只读权限 |
| `X_USERNAME` | 否 | 账号名，不带 `@` |
| `TELEGRAM_BOT_TOKEN` | 否 | 用于读取频道人数的 Bot token |
| `TELEGRAM_ANTI_LOSS_CHAT` | 否 | 防丢频道：`@name`、`https://t.me/name` 或 `-100...` |
| `TELEGRAM_PREVIEW_CHAT` | 否 | 预告频道，格式同上 |
| `STORY_FEED_TTL_SECONDS` | 否 | 缓存秒数，30–3600，默认 300 |

说明：

- **建议单独建一个只读 Bot**：把它加入防丢频道和预告频道即可，不需要管理员权限；不要复用运营 Bot 的 token，避免网站服务器持有能发帖的凭据。
- Telegram 频道若是私有频道，Bot 必须是成员；公开频道能否直接读取以实测为准。
- X 免费套餐通常只能读账号指标，读不了用户时间线。读不到帖子时页面只显示粉丝数，并在预告板块提示进入频道，这是预期行为。
- X 读额度紧张时把 `STORY_FEED_TTL_SECONDS` 调大（例如 1800）。

## 4. 降级矩阵

| 情况 | 数据行 | 预告板块 | 提示 |
|---|---|---|---|
| 全部正常 | 三项 | 最近 3 条带媒体帖文 | 无 |
| X 只有账号指标 | X 粉丝数 | 空态 | 「X 最新内容暂不可用」 |
| X 账号不可读 | 隐藏 X | 空态 | 「X 数据暂不可用」 |
| 只配置 Telegram | 两个频道 | 空态 | 「X 数据暂未接入」 |
| 只配置 X | X 粉丝数 | 正常/空态 | 「Telegram 数据暂未接入」 |
| 全部未配置（生产） | 不显示 | 空态 | 「实时数据暂不可用」 |
| 全部未配置（开发） | 示例数字 | 示例帖文 | 标注「示例数据」 |
| 上游超时/5xx | 隐藏对应项 | 空态或旧数据 | 对应来源不可用 |

生产环境不会显示任何示例数字；开发环境的示例数据只用于设计预览。

## 5. 安全

1. token 只在服务端环境变量中读取，不写入页面、响应、日志或仓库。
2. 错误消息只保留错误类型，不回传上游响应正文、请求 URL 或 token。
3. 帖文图片只接受 `https://pbs.twimg.com` 链接，并统一附加 `name=small`。
4. 接口无写入能力，也没有任何用户数据；`Cache-Control: no-store` 防止 CDN 缓存。
5. 后台管理接口、成年凭据、SQLite 与媒体目录不受本次接入影响。

## 6. 配置后自检

```sh
cd web
npm run integrations:check
```

输出示例（不含密钥）：

```text
接入模式：真实数据
✓ X 账号 @xxx：12,345 粉丝
✓ X 时间线：读取到 3 条带媒体帖文
✓ Telegram 防丢频道 @backup：3,400 人
✓ Telegram 预告频道 @preview：1,900 人
```

- 「△ X 时间线不可读」不算失败，说明当前套餐不支持时间线；粉丝数仍会显示。
- 配置格式错误会在「配置问题」中列出，不会打印 token 内容。
- 退出码非 0 表示已配置的来源确实不可用。

## 7. 生产部署

1. 在服务器 `/opt/cdsexgirl/app/.env.local` 追加第 3 节的变量（0600）。
2. 重启 `cdsexgirl.service`。
3. 运行 `npm run integrations:check`（在应用目录内）确认。
4. 打开 `https://cdsexgirl.com/`，确认年龄门后「个人简介」出现真实数字、「预告」出现真实帖文。
5. 若仍显示「实时数据暂不可用」，检查服务端日志中的 `[story]` 行；日志只包含错误类型。

## 8. 验收清单

- [ ] 未配置时，生产页面不出现 12.8K / 3.4K / 1.9K 等示例数字。
- [ ] 配置 X 后，「个人简介」显示真实粉丝数。
- [ ] X 时间线无权限时，粉丝数仍显示，预告板块给出可用的频道入口。
- [ ] 配置 Telegram 后，两个频道人数与 Telegram 客户端一致。
- [ ] 反复刷新页面不会每次都请求 X（缓存生效）。
- [ ] 浏览器源码、网络响应和日志中都找不到 token。
- [ ] 关闭后端 X / Telegram 网络后，页面仍能正常渲染，只是数据降级。
