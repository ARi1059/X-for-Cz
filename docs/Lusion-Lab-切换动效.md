# Lusion Lab · 五帧切换动效精修

日期：2026-11-03  
入口：`http://localhost:3000/?experience=lusion`（dev + localhost only）  
状态：**已落地；只改 Lab 的切换动效与降级细节，主站 `/` 未改。**

## 1. 为什么之前“卡且怪”

旧版不是“动效不够多”，而是四件事叠在一起：

1. **相机先扭一下再漂。** 选中新帧时，`camera.lookAt(selected.x, …)` 当帧就指向新 x；相机位置却用每帧 0.045 的 lerp 追。视线先跳、机位后到，第一帧就“扭”，随后长尾“漂”。
2. **各元素各用一套 lerp。** 相机 0.045、画面 z 0.08、辉光 0.07、地面线/阴影直接瞬移；倒影纹理在切换瞬间硬切。它们速度不同，永远不在同一拍上；而且 0.08/帧在 60Hz 和 120Hz 上手感不同。
3. **新帧被旧画面挡住。** 选中帧从走廊深处飞向舞台，中间会穿过前面的灯箱；视觉上前半段仍是旧主角，后半段新主角突然“钻出来”。
4. **Retina 合成停顿。** 2× canvas + MSAA 在 headed Chrome 上偶发 100–300ms 的合成停顿；用键盘切换时也能测到。

目标不是“更快”，而是：**起手有回应、过程只认一个主角、落点软、打断不跳。**

## 2. 时间轴（相邻 02 → 03，总 730ms）

| 时间 | 发生什么 |
|---|---|
| 0–150ms | 相机横移起步；朝向以 0.55× 时长轻微领跑；侧框开始压暗、按深度后退 |
| 150–400ms | 新帧从走廊深处滑到舞台；挡在它前面的灯箱按深度让开；旧帧退回自己的槽位 |
| 400–650ms | 新帧落位，金边到 0.72；相机横移完成；其余灯箱回位 |
| 650–1000ms | 只剩镜头呼吸、尘埃、指针视差，不再有切换动作 |

- 曲线：`1 - (1 - smoothstep(p))^1.6`。前 40% 完成约 50%，后 20% 只走 3%，起手快、落点软，无过冲。
- 时长：`640ms + 90ms × 跳帧数`，最多按 3 格算（Home/End 最长 910ms）。
- 打断：cubic Hermite 带速度交接；反向手势从静止开始，不会被上一段速度“拽回去”。
- 入场：初始选中帧直接站在舞台，不再从走廊深处飞入。

## 3. 实现要点

### 一个 glide，负责所有值（历史；当前为 focus 连续采样）

`Glide` 记录 `value/from/to/start/duration/slope/velocity`，用 `performance.now()` 求值，不依赖帧率。  
打断时把当前速度换算成 Hermite 起始斜率，限制在 0–2 之间，保证单调、不过冲。

### 一次滑动只切一帧（历史，滚动模式已不再使用）

- 新旧实现都监听 `wheel`，但旧版用 `420ms` 节流；触控板的惯性事件会在 420ms 后继续到达，被当成第二次手势，于是用户一次滑动会跳 2–3 张。
- 现在改成**手势锁**：第一下 `wheel` 切一帧，之后所有同方向 `wheel`（包括惯性尾段）只把“静止计时器”重置到 **220ms**；220ms 内没有新的同方向 wheel 才解锁。
- **反向滑动立即解锁**：如果新事件方向相反，且距上一次切帧超过 100ms，就不再等静止计时器，立刻切回去。这样“下滑后马上上滑”不会被惯性尾段吞掉；100ms 只是过滤触控板的抖动。
- 只忽略纯水平滑动（`|deltaY| < 0.01`）；带垂直分量的斜向滑动仍然生效。按住方向键的 `repeat`、HUD 上按住 Enter/Space 的重复事件也忽略。
- 结果：一次连续滑动 = 一帧；同方向连切需要停 220ms，反向纠正无需等待。调参入口是 `light-gallery.tsx` 的 `WHEEL_GESTURE_IDLE` 和 `WHEEL_REVERSE_GUARD`。

### 相机是固定轨道，不穿走廊

- `z = 7.6` 固定；只动 x。
- `railX` 用完整时长到新帧；`lookX` 用 0.55× 时长先到，形成“先看过去、机位再跟上”的轻摇，而不是瞬间转头。
- 没有采用相机 dolly：相机走近中间帧时，近景灯箱会短暂“糊脸”，需要更激进的淡出，风险更大。

### 选中帧先到家

- 选中帧：`z → 0.4`、`scale → 1.045`、`photo → 1`、`edge → 0.72`，用 0.8× 时长。
- 旧帧：用 0.72× 时长退回原 z 并压暗，先让出舞台。
- 其余帧：1× 时长回位，形成“新主角先落、旧主角先退、镜头最后停”的层次。

### 只做深度让位，不做横向扇形

新帧还在走廊深处时，所有 z 比它靠前的灯箱按

```
overlap = max(0, z_frame - z_hero + 1.3)
recede  = min(2.8, overlap) × opening
```

向后退，`opening` 是 0 → 1 → 0 的包络，并用 12/s 的指数阻尼跟随。  
这样走廊只是“吸一口气”，不会把五帧摊成一排；新帧不会长时间被旧帧吞掉。

### 倒影跟着自己的画走

每个灯箱都有自己的地面倒影，随它的 z 一起移动，透明度跟随画面透明度平方。  
不再在切换时替换唯一那张倒影的纹理，因此没有硬切。

### 性能与降级

- `pixelRatio = min(devicePixelRatio, 2)`；**DPR ≥ 1.5 时关闭 MSAA**（2× 屏幕上金线本身约 2 个设备像素，画质损失很小）。1× 屏幕保留 MSAA。
- HUD 去掉 `backdrop-filter`，改为高不透明度底色；固定小面板不再每帧触发背景模糊合成。
- HUD 的「上一帧 / 下一帧」从原生 `<button>` 换成 `role="button"` 的 div，保留 `tabIndex`/`aria-disabled`/Enter/Space。本机 Chrome 实测：原生 button 在这个页面上 hover 会触发一次约 100ms 的合成停顿，div 不会；切换路径（鼠标点击）也因此稳定。
- 隐藏的 2D fallback `<img>` 不再随 `labIndex` 改 `src`，避免每次切换都解码一张全屏 JPEG；场景失败时仍会切到当前帧。
- 五张纹理加入 `disposables`，场景卸载/静态模式切换时释放。
- 隐藏页签暂停 rAF，恢复时平移 glide 起点，不会“补帧”跳到终点。

## 5. 取舍说明

- **不做相机前进**：五帧走廊的纵深靠固定机位和 z 差表达；相机穿行会让中间帧瞬间变大、需要淡出，反而更“怪”。
- **不做横向让位**：横向推开会把“走廊”读成“五连拍”。
- **不做 CSS 模糊/滤镜**：成本高，且解决不了前后遮挡；用深度让位 + 压暗更便宜。
- **2× 关 MSAA**：这是本次最大的性能取舍。金线在 2× 下仍有约 2 个设备像素宽；如果以后要更锐，可以加一次 FXAA/SMAA 全屏 pass，但要重新测帧率。
