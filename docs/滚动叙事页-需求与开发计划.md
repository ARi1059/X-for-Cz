## 0. 一句话

把现在的「五帧 3D 光廊」升级为一页**五段式滚动叙事**：页面背景随滚动在五张人像之间渐进切换；左侧面板从「与我相遇」依次替换为个人简介、预告频道、会员权益、购买教程；底部中央有一个下拉提示；Telegram 私人号按钮改为「Telegram 防丢主页」。

## 1. 当前基础与本次改动

### 已经有

- 五张人像背景（`web/public/lusion/01–05.jpg`，1024px 长边，仅 Lab）；
- 原生滚动驱动的 5 站轨道 + `sticky` 视口；左侧导航/顶栏/页脚/HUD 固定；
- 每站背景是 3D 走廊里的一个灯箱，滚动时连续交接；
- 现有 5 个入口链接（X、Telegram 个人、Telegram 预告频道、OnlyFans、会员购买）；
- 草稿/发布、年龄门、媒体库、后台、e2e（36 项）和构建。

### 本次要改

1. **背景**：从“3D 灯箱走廊”变成“网页整屏背景的动态切换”；滚动时上一张渐隐、下一张渐显。
2. **左侧内容**：不再全程固定为“与我相遇”；五段内容随滚动切换，面板位置固定。
3. **底部下拉提示**：页面底部中央增加向下的箭头/提示，点击进入下一段。
4. **Telegram 入口**：「Telegram 私人号」改为「Telegram 防丢主页」，并说明它是永久入口。
5. **新增四段内容**：个人简介（平台粉丝数据实时更新）、预告频道内容、会员有什么、会员购买方式及教程。

### 不在本次范围

- 不在站内收款、不存卡号、不做支付页；
- 不抓取 OnlyFans 或私密频道；
- 不做自动发布私密内容；
- 不做假的“实时”数字（没有数据源时明确标注手动/更新时间）；
- 不改年龄门、法律声明、主站 CTA 规则。

## 3. 交互与视觉

### 3.1 背景动态切换：两个方案，需先定

**方案 A（推荐）：2D 整屏背景交叉淡入淡出**

- 五张人像作为整页背景；上一张/下一张两层 `<img>` 叠放，透明度随滚动进度变化。
- 人像放在右侧约 55–62% 宽度，保持原比例；后面叠一层放大、模糊、压暗的环境底图；左侧用深色渐变保证文字可读。
- 不用 WebGL；性能稳定，移动端也能用；更符合“网页背景”的直觉。
- 3D 五帧走廊从本页主流程退场，保留为 Lab 历史/可选模式。

**方案 B（保守）：保留 3D 五帧走廊作为背景**

- 仅把左侧内容做成五段切换；背景仍是现有的 3D 灯箱，滚动时换主角。
- 工作量少一天左右，但内容多后画面会更“满”，文字和灯箱容易互相抢。
- 如果用户更认可现有 3D 质感，选 B；否则选 A。

**建议**：先用 10 秒视觉对比决定 A/B，再进入开发；本计划默认 A。

### 3.2 页面骨架

- 5 屏滚动轨道（`500svh`）；可见视口 `position: sticky`。
- 背景固定；左侧面板固定；内容随当前站点替换。
- 顶部/底部品牌栏保持固定；右下保留最小站点索引（`02 / 05` 或竖排 01–05）。
- 底部中央：下拉提示按钮。
- 桌面：左侧面板 400–460px；右侧背景人像。
- 移动端：不再用固定面板；五段内容按正常文档流堆叠，每段一屏左右，背景随段落切换；下拉提示保留。

### 3.3 内容切换

- 背景：连续交叉淡入淡出，滚动停止时停在当前背景。
- 面板：在站点阈值附近做 300–400ms 的淡入 + 8px 上移；旧面板绝对定位，避免高度跳动。
- 站点判定：当前 scroll 进度最接近的站点；内容切换阈值建议 50–55%，避免背景还没换完文字先换。
- 每段内容长度不同；桌面面板设置最小高度，超长内容用**摘要 + “展开完整教程”弹层**，避免面板内滚动和页面滚动打架。
- 05 的完整教程可以放在现有 `lg-dialog` 风格的弹层里；桌面/手机都可读。

### 3.4 底部下拉提示

- 位置：底部中央，页脚上方；不压住页脚和 HUD。
- 形态：1px 金色细线 + 40–44px 圆形按钮 + 向下 chevron；下方可选 `SCROLL` 小字。
- 动效：2.4s 轻微上下浮动；hover/focus 时停下；`prefers-reduced-motion` 时静止。
- 行为：点击平滑滚动到下一站；键盘可聚焦、Enter/Space 触发；`aria-label="滚动到下一节：个人简介"`。
- 05 时：隐藏，或在原位变为“回到顶部”；建议隐藏，并在 05 面板放一个“回到顶部/返回导航”文字链接。
- 移动端：固定在安全区上方，避免与浏览器底栏重叠。

### 3.5 可读性与品牌

- 左侧面板用深色渐变/半透明底，不额外加大卡片阴影；保留“私人版”气质。
- 数字使用大号衬线/等宽数字；标签小号字距；和现有香槟金一致。
- 背景压暗到能读正文；人像仍然是主角，但不抢文字。
- 动效只做交叉淡入、轻微缩放（1.03→1）和内容 8px 位移；不做花哨转场。

### 3.6 无障碍与降级

- `prefers-reduced-motion`：背景直接切换，不做缩放/浮动；内容直接替换。
- 静态模式：停用背景动效，显示当前段背景；下拉提示仍可用。
- 移动端：内容按文档流，保证字号/对比度；下拉提示可点击。
- 屏幕阅读器：每段有明确标题；内容切换时用 `aria-live="polite"` 只播报标题，不播报整段正文；下拉提示有可读标签。
- 键盘：Tab 可到下拉提示、站点索引和 CTA；滚动本身用原生键盘。

## 4. 数据与内容模型

### 4.1 Telegram 防丢主页

- 复用现有 `tg_personal` ID（保持 `/go/tg_personal` 路由和历史点击统计），只改：
  - `label`：`Telegram 防丢主页`；

  - `url`：待用户提供；

- 同步更新：

  - 已发布草稿/线上配置（后台改，或迁移脚本）；

- 需要确认真实 URL 是频道、群、Bot 还是导航页；如果是频道，粉丝数可自动取；如果是 Bot/落地页，只能手动或省略计数。

### 4.2 平台粉丝数据（实时/近实时）

**原则**：不伪造“实时”。UI 显示数字 + `更新于 HH:mm`；过期显示“数据延迟”；没有数据源时显示手动更新。

| 平台 | 可取数据 | 现实方案 |
|---|---|---|
| X | followers_count | X API v2；需要 bearer token；有付费/限额；缓存 10–15 分钟 |
| Telegram 预告频道 | 订阅数 | Bot API `getChatMemberCount`；Bot 需在频道内有权限；缓存 5–10 分钟 |
| Telegram 防丢主页 | 订阅数 | 同上；若是频道/群；若是 Bot/落地页则不可取 |
| OnlyFans | 粉丝/订阅数 | **没有官方公开 API**；只能后台手动填，或不显示数字只放 CTA；不抓取 |
| 会员平台 | 会员数 | 有 API 才自动；否则手动 |

**数据模型**（建议独立于发布快照，因为它是实时值）：

- `platform_stats`：`platform`、`label`、`handle`、`count`、`source`（`api`/`manual`）、`status`（`fresh`/`stale`/`error`）、`updated_at`、`visible`、`order`。
- 对外 API：`GET /api/public/story/stats`，返回格式化数字、更新时间、状态；`Cache-Control: s-maxage=300, stale-while-revalidate=900`。
- 刷新策略：
  - P1：后台手动填/刷新，先保证页面完整；
  - P2：服务端按需刷新（缓存过期后后台拉取，返回上次值），不引入外部 cron；
  - P3：可选 cron/CLI 定时刷新。
- 安全：token 只在服务端 env；不把任何平台密钥发到浏览器；接口只返回公开数字。
- 合规：遵守各平台条款；不抓 OnlyFans；不展示可反推出私密信息的数据。

### 4.3 预告频道内容

- P1 推荐**后台手动选 3–4 条**：运营者从预告频道挑已公开内容，上传缩略图/填 1–2 行字/填原帖链接；可控、无抓取风险。
- P2 可选自动：Bot 在频道内接收新帖（`getUpdates`/webhook），保存文本与媒体 ID，人工审核后展示；需要 Bot 权限和审核流程。
- 不做 `t.me/s/` 网页抓取（易碎、条款风险）。
- 数据字段：`id`、`channel`、`text`（≤180 字）、`mediaId`（可空）、`publishedAt`、`url`、`visible`、`order`；最多 4 条。
- 媒体复用现有媒体库；发布时校验媒体 ready；只展示预告，不展示付费内容。

### 4.4 会员权益

- 字段：`id`、`title`（≤24 字）、`body`（≤120 字）、`icon`（枚举/现有 lucide 图标）、`order`、`visible`；最多 6 项。
- 先确认是单档还是多档；如果是多档，增加 `tier` 字段和价格/周期；本计划先按单档设计，预留 tier。
- 不在页面写会过期的价格，除非用户明确要展示；购买价格放在外链/弹层说明。
- 文案需要用户确认；可先用 4 项示例占位。

### 4.5 购买方式与教程

- 购买方式：`id`、`label`、`description`、`linkId`（复用 `/go/membership` 等）或 `url`、`visible`、`order`。
- 教程步骤：`id`、`title`、`body`、`order`；3–5 步。
- FAQ：复用现有 `info.faq` 的结构，或放在 `story.purchase.faq`；最多 6 条。
- 站内不收款；CTA 走现有 `/go/:linkId` 外链确认流程；不收集卡号。
- 若涉及 USDT/订单，沿用 `06-Telegram-Bot开发需求.md` 的边界；网站只解释流程和跳转。
- 需要用户提供：具体购买平台、步骤截图/文案、开通时效、退款/防骗说明。

### 4.6 配置、后台与迁移

## 5. 技术方案（概要）

### 前端

- 新组件（名称暂定）`StoryScroll`：
  - 5 个 section 的滚动轨道；sticky 背景与面板；
  - 滚动进度 → 背景交叉淡入 + 当前站点；
  - 面板内容切换；
  - 下拉提示/站点索引。
- 2D 背景：两层 `<img>` + `object-fit`/`object-position`；预加载下一张；LQIP；不引入新依赖。
- 媒体：从现有受控媒体库取 1600–2000px 长边衍生图；生成 WebP/AVIF；保留竖图比例；桌面右侧人像、移动端全屏压暗。
- 若选 3D 方案 B：复用现有 `LusionScene` 的连续 focus；面板内容切换与场景站点同步。
- 数据：`GET /api/public/story`（发布内容）与 `GET /api/public/story/stats`（实时/缓存）；页面首屏服务端取内容，stats 客户端刷新/轮询。避免 stats 阻塞 LCP。
- HUD：保留最小 `01 / 05`；下拉提示独立；05 隐藏提示。
- 可访问性：每段标题、aria-live 标题、按钮 label、reduced-motion。

### 服务端

- 扩展配置 schema、publication projection、admin API、迁移；
- stats adapter 接口：`fetchX`/`fetchTelegram`/`manual`；统一缓存/超时/降级；
- 只读公开 API；不返回 token；
- 统计接口限流/缓存；
- 后台校验与发布流程复用。

### 性能目标

- 桌面 1440/1920：55–60fps；滚动无长任务；背景切换不导致布局抖动；
- 移动端 390：无横向溢出；背景图不阻塞首屏；
- LCP 首图预加载；其余背景 lazy；
- 对比现有 36 项 e2e，新增叙事/下拉/内容/数据用例，保持通过。

| P4 实时数据 | stats API/缓存/手动覆盖、X/Telegram adapter、OnlyFans 手动、状态/更新时间、监控 | 近实时数据（G2） | 1–2d |

**最早可评审**：P2 结束（约第 3 天）先看视觉/滚动；P3 结束（约第 4–5 天）看真实内容；实时数据在 P4。

### 里程碑

- **G0**：P2 后，1440/390 看 10 秒；确认“背景是背景，不是卡片走廊”、文字可读、下拉提示不挡内容。
- **G1**：P3 后，五段内容、Telegram 名称、后台发布流程可用；无占位。
- **G2**：P4 后，四个平台数据按口径展示，失败/过期有兜底；不出现假实时。
- **G3**：P6 后，e2e/构建/性能/法务通过；决定是否从 Lab 进生产。

### 依赖

- 用户提供：防丢主页 URL、各平台账号/API 权限、预告内容选片、会员权益/价格/购买方式/教程、简介文案、主站/Lab 范围。
- 技术依赖：X API 额度、Telegram Bot 管理员权限、媒体库现有衍生能力。
- 没有 API 时：P4 降级为手动数据；仍可完成 P0–P3。

## 7. 验收标准

### 功能

- 5 段内容按滚动出现/替换；左侧面板在桌面固定，内容切换不引起布局跳动；
- 背景随滚动渐进切换，停止时停在当前背景；上一张/下一张无闪烁；
- 底部中央下拉提示可点击/键盘触发，进入下一段；05 隐藏或回到顶部；
- Telegram 防丢主页名称/链接正确，旧“私人号”不再出现在 Lab；
- 个人简介显示平台数字 + 更新时间；失效/过期有明确状态；
- 预告卡片 3–4 条，链接可打开；不泄露付费内容；
- 会员权益/购买方式/教程/FAQ 可读，CTA 走现有外链确认；
- 手机 390 正常；reduced/static 无动效或降级；年龄门/页脚/站点说明不回归。

### 数据

- 不伪造数字；每个数字有来源和更新时间；
- stats 失败时返回上次值/手动值，不白屏；
- OnlyFans 若无可信来源，使用手动或省略，不抓取；
- 发布校验覆盖所有新增媒体/URL/文本长度。

### 质量

- 现有 36 项 e2e 全过；新增叙事/下拉/内容/数据用例；
- `npm run check`、`npm run build` 通过；
- 桌面 55–60fps；无长任务；移动端无横向滚动；
- 对比度、字号、焦点、aria、reduced-motion 通过；
- 内容/法务复核：年龄、同意、平台条款、隐私。

## 8. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| OnlyFans 无公开 API | “实时”做不到 | 手动/省略；明确标注 |
| X API 额度/费用 | 数据不更新 | 缓存 + 手动覆盖 + 过期提示 |
| Telegram Bot 无频道权限 | 取不到订阅数 | 先手动；补 Bot 管理员 |
| 背景图竖图被裁 | 人像不完整 | 右侧人像 + 环境底图；`object-position` 调焦 |
| 内容变多后面板放不下 | 文字拥挤/内滚 | 摘要 + 弹层；控制每段字数 |
| 3D 与内容抢视觉 | 可读性差 | 选 2D 背景或强压暗 |
| 5 屏滚动太长 | 用户中途离开 | 下拉提示、站点索引、每段一个主动作 |
| 预告内容版权/泄露 | 合规风险 | 只用手动审核过的公开预告 |
| 主站/Lab 边界不清 | 影响正式页 | 先 Lab；生产另立 G3 |

## 9. 需要你确认的 8 件事

1. **背景方案**：选 A（2D 整屏交叉淡入，推荐）还是 B（保留 3D 光廊）？
2. **Telegram 防丢主页**：URL 是什么？是频道/群/Bot/导航页？描述用哪句？是否作为唯一主入口？
3. **粉丝数据**：要展示哪几个平台？X/Telegram 是否有 API/额度？OnlyFans 数字手动还是省略？5–10 分钟更新算“实时”可以吗？
4. **预告内容**：先手动选 3–4 条，还是自动从频道同步？具体哪几条/是否已授权公开？
5. **会员**：单档还是多档？权益是哪 4–6 条？价格是否展示？购买方式是 OnlyFans / USDT / 其他？教程每一步是什么？
6. **范围**：先只做 Lab，还是最终要上生产 `/`？如果上生产，是否替换现有的人像导航页？
7. **移动端**：五段内容按正常文档流堆叠可以吗？下拉提示在手机上保留吗？
8. **文案**：个人简介、五段标题、会员/购买文案由你提供，还是我先按本文草案写一版给你改？
