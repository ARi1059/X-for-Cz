# Lusion Lab v2 · 五帧空间

日期：2026-11-03  
输入：你上传的 5 张 1280×1707~1920 人像。  
问题：这 5 张能否变成 Lusion 式空间？  
结论：**能，但不是把 5 张图放进现有单帧场景；需要把“相框”改成“走廊”。**

## 1. 为什么单帧不行

单张人像 + 墙 + 地面 + 反射，最后还是“一幅画”。

- 只有一个平面，没有遮挡、前后景、尺度变化；
- 相机只能轻微平移，空间关系不变；
- 观众看到的是“框里的她”，不是“她所在的房间”。

**5 张图的价值不是数量，而是能让画面之间产生前后、遮挡和镜头运动。**

## 2. 推荐概念：After Hours / Five Frames Corridor

一条很暗的私人画廊走廊，5 幅人像作为 5 个**发光灯箱**，错落在不同深度：

```
相机 →
[01 绿色 z0]   [02 红色 z-1.5]   [03 白色圣诞 z-3]
        [04 粉色 z-4.5]   [05 白色皮草 z-6]
```

- **红色**是 hero：它本身有走廊/地毯的纵深，最适合作为空间锚点。
- 绿色、粉色、白色作为侧翼，部分被前景遮挡。
- 相机沿 z 轴缓慢前进/后退；选中的画面前移、其他后退。
- 地面反射、墙面光池、薄金框、悬浮尘埃保留；不再加第二个 3D 物体。
- 左侧 1+4 导航与主入口不动；3D 只是背景空间，不抢 CTA。

### 关键不是“五连拍”

不做：

- 5 张并排一面墙；
- 5 张同一 z 深度的 grid；
- 5 张自动轮播；
- 5 张都清晰可见。

要做：

- 同一时间只看到 2–3 张；
- 近景遮挡远景；
- 相机移动时尺度变化；
- 红色 hero 与绿色/粉色形成前后关系；
- 地面/墙/光让画面“站”在空间里。

## 3. 5 张图的角色

| 图片 | 角色 | 原因 |
|---|---|---|
| 绿色 Dior | 前侧景 | 白色墙面 + 品牌字，适合做入口第一帧 |
| 红色长裙 | **hero** | 走廊/地毯天然有纵深，颜色最强 |
| 白色圣诞 | 中景 | 亮背景，形成呼吸 |
| 粉色楼梯 | 侧景 | 曲线/扶手，增加方向感 |
| 白色皮草 | 远景 | 收尾，和绿色形成前后呼应 |

## 4. 交互

- 桌面：滚轮/方向键/点击侧边画面 → 相机在 z 轴前进/后退；选中画面前移。
- 不劫持页面滚动：Lab 是固定视口，滚轮只驱动场景。
- 手机 / reduced / static：直接回 2D 光廊，不挂 5 个 canvas。
- 主站 `/` 不动；Lab 仍是 dev-only。

## 5. 技术

- 复用现有 `LusionScene` 的相机/地板/反射/光池/尘埃；
- `LusionScene` 从单纹理改成 **5 个 plane**；
- 5 张图复制到 `web/public/lusion/01..05.jpg`，用 `TextureLoader` 加载；
  - lab 只加载 5 张静态图，不走 `/media`，不影响主站媒体；
  - 1024px 长边压缩，控制显存；
- 一个 canvas；无新依赖；
- 选中索引驱动相机 z 和画面 z，不使用滚动劫持；
- 5 个 plane 的遮挡/深度是核心，不增加粒子/第二个 3D 物体。

## 6. 3 天原型

| 天 | 工作 | 产出 |
|---|---|---|
| Day 1 | 复制 5 图；5 plane 布局；红色 hero；相机 z 走廊 | 静态五帧空间 |
| Day 2 | 滚轮/方向键/点击选帧；相机移动；反射/墙/光 | 可交互走廊 |
| Day 3 | 性能/降级/e2e/1440/390 截图；与单帧、2D 对比 | 决策包 |

## 7. 验收

- 同一时间只看到 2–3 张；有明显的近大远小和遮挡；
- 第一眼不是“五张并排”，而是“走廊里的五个灯箱”；
- 5 张图加载后仍 55–60fps；
- 手机/reduced/static 2D；
- 主站 35 项 e2e 不回归；
- 如果仍然像“相框/五连拍”，直接归档，不再加几何。

## 8. 结论

**这 5 张图可以变成 Lusion 式空间，而且比单张更有机会。**  
但前提是：把它们做成**有纵深、有遮挡、有镜头运动的五帧走廊**，而不是五张并排的画。

下一步：如果你确认，我按这个方向做 3 天 Lab v2；仍然只动 dev-only Lab，不碰主站。

## 10. 修正：图片被挤压（2026-11-03）

原因：5 张图里 01/03 是 3:4（0.75），02/04/05 是 2:3（0.667），但所有 plane 都用了 2.25×3.0（0.75），导致 02/04/05 被横向拉伸。

修正：

- 高度保持 3.0；
- 每张 plane 宽度 = `3.0 × 原图宽高比`；
- 框、框厚、金线、倒影宽度都跟随实际宽度；
- 不做裁切、不做拉伸；
- 2D fallback 继续 `object-fit: cover`（裁切而非变形）。

实际宽度约：

| 图片 | 比例 | plane 宽度 |
|---|---|---|
| 01 绿色 | 3:4 | 2.25 |
| 02 红色 | 2:3 | 2.01 |
| 03 白色 | 3:4 | 2.25 |
| 04 粉色 | 2:3 | 2.00 |
| 05 白色皮草 | 2:3 | 2.00 |

结果：红色/粉色/白色皮草恢复修长，绿色/白色保持原比例；三帧走廊关系不变。

验证：`npm run check` 47；完整 e2e **35/35，1.3m**；build 通过。  
证据：`web/var/screenshots/M3-lusion-v2-2026-11-03/five-frame-corridor.png`（已按新比例重截）。

## 11. 切换动效精修（2026-11-03，历史：离散切换版本）

**问题：** 旧版切换同时叠了四件事——相机朝向瞬间跳到新 x、机位用 0.045/帧去追；五帧/辉光/地面线/倒影各用一套 lerp；选中帧从走廊深处飞向舞台时会被前方灯箱挡住；2× Retina + MSAA 偶发 100–300ms 合成停顿。所以看起来“先扭一下、再漂过去、新帧后半段才冒出来”。

**修正：**

- 一个带速度交接的 cubic-Hermite `Glide` 管所有值；`performance.now()` 求值，60Hz/120Hz 同一条曲线；
- 相机固定 z=7.6 只横移；朝向 `lookX` 用 0.55× 时长领跑，先看过去、机位再跟上；
- 新帧用 0.8× 时长先到舞台；旧帧用 0.72× 时长先退；镜头和其余灯箱 1× 时长收尾；
- 新帧还在后面时，前方灯箱只做**深度让位**（最多 2.8）并压暗 0.34，不做横向扇形；
- 每个灯箱带自己的地面倒影，随 z 移动；切换不再硬切倒影纹理；
- 初始选中帧直接站在舞台，不再从深处飞入；
- DPR ≥ 1.5 关闭 MSAA；HUD 去掉 `backdrop-filter`；隐藏的 2D fallback 不再随 `labIndex` 解码新图；
- 纹理加入 `disposables`，场景卸载时释放。

**结果：** 相邻切换 730ms，Home/End 最长 910ms；headed Chrome 1440×1000 DPR2 键盘切换 median 16.7ms / p90 17.7ms，采样 0 帧 > 40ms。`npm run check` 47/47；`npm run test:e2e` **35/35**（首次冷启动 32/35，3 个门禁用例复跑 3/3 通过）。
